# ADR-002 — The C ABI / FFI contract

## Context

The Dart↔C++ boundary is a product surface, not an implementation detail (D4).
Everything the UI will ever know about the engine passes through it, and every
mistake made here ossifies: by v0.4 there will be a sequencer, a mixer and an
export pipeline sitting on top of whatever shape we choose now (R5).

NFR-10 fixes the shape in one sentence — **commands in, snapshots out** — and
NFR-06 fixes the constraint: Dart never polls, allocates on, or blocks the audio
thread. This ADR turns those into a concrete contract and records why each part
is the way it is.

The header is normative. Where this document and `onebeat_abi.h` disagree, the
header wins and this document is the bug.

## Decision

### 1. Versioning

`ob_abi_version()` returns a packed `(major << 16) | (minor << 8) | patch`.
The Dart client checks the **major** on startup and refuses to run on a
mismatch, with a message that says what to do (`tools/build.sh`) rather than a
crash three calls later.

Bindings are generated by `ffigen` from the header (`app/ffigen.yaml`), and the
generated file is checked in so that a clone builds without libclang. Hand-written
bindings are forbidden: two sources of truth for a struct layout is how a field
silently shifts.

**Why not a handshake struct or a capability negotiation?** There is exactly one
client, shipped in the same repository, in the same build. A version check is
enough; anything richer is speculative generality.

### 2. Lifecycle and errors

`ob_engine_create` / `ob_engine_destroy`, plus `ob_engine_start` / `ob_engine_stop`
for the device. Every function returns an `ob_status`; failures set a
**thread-local** message retrieved with `ob_last_error_message()`.

**No exception ever crosses the boundary.** Every entry point in
`onebeat_abi.cpp` is wrapped in a `try`/`catch(...)` that converts to a status
code. A C++ exception unwinding into Dart's stack is undefined behaviour, and
"we don't throw in that path" is not a guarantee, it is a hope.

The error message is thread-local rather than global so that two threads failing
at once cannot overwrite each other's message.

### 3. Command channel (UI → engine)

`ob_engine_post_command(engine, &command)` pushes a 32-byte POD onto a bounded
lock-free ring drained by the audio thread at the top of each block.

- **Fire-and-forget.** Returns `OB_ERR_QUEUE_FULL` rather than blocking. A UI
  thread that blocks on the audio thread is the bug this whole design exists to
  prevent (NFR-06).
- **Generic fields** (`i64_a`, `f64_a`, `f64_b`) rather than a union of
  per-command structs: adding a command type in Stage 2 must not change the
  struct layout, because changing the layout is a major-version event.
- **Generation counter**, assigned by the client and echoed in the snapshot as
  `last_command_generation`, so the UI can tell whether a command has landed
  without a synchronous round trip.
- Commands take effect **at the next block boundary**, never mid-block. This is
  what makes "seek while playing" click-safe rather than accidental.

**Why not the third-party queue we vendored (`readerwriterqueue`)?** Every
function on the audio thread must be *provably* nonblocking under Clang's
function effect analysis (`-Wfunction-effects`). A queue whose internals carry no
effect annotations forces a blanket warning suppression over the hottest code in
the engine, which is precisely where we least want to switch the checking off.
The in-house bounded ring (`engine/src/core/rt/mpsc_ring.h`, Vyukov's algorithm)
is sixty lines, is annotated throughout, and costs less than that hole.

### 4. Snapshot channel (engine → UI)

`ob_engine_read_snapshot(engine, &out)` copies the most recent consistent
`ob_snapshot` into **caller-owned** memory.

- The audio thread is the only writer. It publishes through a **seqlock**: bump
  the sequence to odd, write the payload, bump to even. Readers retry while the
  sequence is odd or changed under them, with a **bounded** retry count so a
  reader can never spin behind a descheduled writer.
- The payload is stored as an array of `std::atomic<uint64_t>` words rather than
  a plain struct. The race a seqlock makes *safe* is still a data race as far as
  the language (and TSan) is concerned; using atomics with relaxed ordering makes
  it legal as well as correct, and keeps TSan green without suppressions.
- The struct has a **fixed layout with no implicit padding**, frozen field by
  field in `engine/tests/test_abi.cpp`. That test failing means either a revert
  or a deliberate major-version bump — never a quiet edit.
- The Dart side allocates **one** `ob_snapshot` at startup and reuses it, so the
  per-frame path allocates nothing on either side of the boundary.

**Why a C call per frame rather than exposing the buffer to Dart directly?**
Handing Dart a pointer to seqlock-protected memory means implementing the retry
protocol in Dart, correctly, forever. One FFI call per frame costs well under
0.1 ms and keeps the protocol in one place, in the language that owns it.

**Why sample rather than push?** A push channel makes the engine responsible for
UI cadence, and couples audio-thread work to how fast the UI happens to be. The
UI reads at its own frame rate and gets the freshest consistent value; if it
drops a frame it simply misses one, which is exactly the right behaviour for a
meter.

### 5. Event channel (engine → UI)

Occasional, non-frame-rate notifications — device changes, errors, sample
loaded, xruns — go through a bounded multi-producer ring drained by
`ob_engine_poll_event` once per UI frame. Producers are the audio thread *and*
the worker threads, so the ring is MPSC; the consumer is the UI thread alone.

Events carry a fixed 96-byte UTF-8 text field rather than a pointer, so there is
no ownership question and nothing to free.

**Why polling rather than `NativePort`/`Dart_PostCObject`?** The UI already ticks
every frame to read the snapshot. Draining a queue in the same tick costs one
extra FFI call and removes an entire category of lifetime and isolate-affinity
problems. If an event ever needs to wake a sleeping UI, that is an additive
change.

### 6. Threading contract

| Function | Thread | May block |
|---|---|---|
| `ob_abi_version`, `ob_abi_version_string`, `ob_status_name` | any | no |
| `ob_last_error_message` | any (thread-local result) | no |
| `ob_engine_create`, `ob_engine_destroy` | main/UI only | yes |
| `ob_engine_start`, `ob_engine_stop` | main/UI only | yes |
| `ob_engine_post_command` | UI only (single producer) | no |
| `ob_engine_read_snapshot` | any | no |
| `ob_engine_poll_event` | UI only (single consumer) | no |
| `ob_engine_load_sample` | main/UI (returns immediately, completes on a worker) | no |
| `ob_engine_set_step_pattern` | main/UI | briefly |
| `ob_engine_output_device_name` | main/UI | no |
| `ob_engine_instance_add`, `ob_engine_instance_remove` | main/UI | yes (helper lifecycle) |
| `ob_engine_instance_count`, `ob_engine_instance_at` | main/UI | no |
| `ob_engine_param_at` | main/UI | briefly (helper control channel) |
| `ob_engine_instance_editor_open`, `ob_engine_instance_editor_close` | main/UI | briefly (helper window) |
| `ob_engine_session_save`, `ob_engine_session_load` | main/UI | yes (filesystem + state) |
| `ob_engine_instrument_*`, `ob_engine_project_*` | main/UI | briefly (model edit + flatten/publish where applicable) |
| `ob_engine_rack_pattern`, `ob_engine_rack_row_count`, `ob_engine_rack_row_at` | main/UI | no |
| `ob_engine_rack_set_row_grid` | main/UI | no |
| `ob_engine_rack_set_length`, `ob_engine_rack_set_swing`, `ob_engine_rack_toggle_step`, `ob_engine_rack_set_step_velocity`, `ob_engine_rack_remove_sequence` | main/UI | briefly (model edit + flatten/publish) |
| `ob_engine_rack_gesture_begin` | main/UI | no |
| `ob_engine_rack_gesture_commit`, `ob_engine_rack_gesture_abort` | main/UI | briefly (flatten/publish) |

The engine handle is owned by the Flutter UI isolate. Debug builds assert the
contract; the per-function documentation in the header is the authority.

### 7. Strings and blobs

All strings are UTF-8. Strings passed **in** are copied by the engine before the
call returns, so the caller may free immediately. Strings returned **out** point
to engine-owned storage valid until the next call to the same function on the
same thread; the caller never frees anything the engine returned.

### 8. Evolution policy

Within a major version, changes are **additive only**:

- new `ob_command_type` / `ob_event_type` values — always allowed, they do not
  touch a layout;
- new functions — allowed;
- new fields **appended** to `ob_snapshot`, with `struct_size` letting an older
  reader ignore the tail — allowed, minor bump;
- reordering, resizing, repurposing or removing a field — **major bump**, with a
  migration note in this ADR.

#### Checklist for any change to `onebeat_abi.h`

Referenced by `CONTRIBUTING.md`; every ABI PR answers these in its description.

1. Is this additive under §8? If not, why is a major bump justified now?
2. Does the header still compile as C (`ctest -R abi_header_is_c`)?
3. Are the new/changed offsets recorded in `engine/tests/test_abi.cpp`?
4. Is the thread and blocking behaviour of every new function documented in the
   header and in §6 of this ADR?
5. Who owns any new pointer, and who frees it (§7)?
6. Does the UI path stay allocation-free per frame?
7. Have the bindings been regenerated (`cd app && dart run ffigen`) and checked in?
8. Has a human reviewed it? FFI-boundary code has no exceptions to this (R4).

## Consequences

- The UI can only ever ask for things the ABI exposes. That is the point: it
  keeps the boundary small and deliberate, and it makes each new capability an
  explicit decision rather than a drive-by.
- Snapshot growth is the expected shape of change — Stage 3 adds playhead and
  selection state, Stage 4 adds per-track metering. The `struct_size` field and
  the freeze test are what make that safe.
- A synchronous "ask the engine and wait" call does not exist and will not be
  added. Anything needing a reply comes back as a snapshot field or an event.

## Alternatives considered

- **A larger, more object-oriented ABI** (per-track handles, getters and
  setters). Rejected: every getter is a synchronous call into state the audio
  thread owns, which is the coupling NFR-06 forbids.
- **Protocol buffers / flatbuffers across the boundary.** Rejected: a dependency
  and a serialisation cost for a boundary that is inside one process and one
  build.
- **Dart FFI callbacks from the audio thread.** Rejected outright: entering the
  Dart runtime from a real-time thread allocates and may block.
